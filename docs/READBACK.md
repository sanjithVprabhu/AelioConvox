# READBACK — comprehension check of `AELIO_DSL_MOTHER.md`

Per Phase 0 of the handoff: for each Part, what it mandates in my own words + what surprised me. This is a comprehension check, not a summary; surprises are the point. Section citations are to the mother doc.

## Part I — Positioning & Guarantees (§1–§3)
Aelio is an **agent operating system**, not an LLM harness: a closed kernel of ops + declared flows, with Sol Contracts as the wire language and Sunjet as the store; the LLM only *authors and repairs* logic behind a promotion gate, never runs the kernel per-turn. The product refuses general computation, open-ended planning, and arbitrary code — the instruction set is closed and the only executable artifacts are gated/registered/versioned. §2 answers the killer question ("why not have the LLM write Python once and replay it?") with **seven guarantees generated code can't give**, each traced to a *locked mechanism* (termination theorem, bit-identical replay, structurally-unbypassable policy, verifiable LLM output, least privilege, safe multi-tenant learning, cross-version migration). §3 is a threat×defense table; the highlighted #1-by-damage threat is **semantically wrong promotions** (the `active≡loggedin` class), defended by the §16 gate + reach-based review.
**Surprise:** the honesty column in §2 — the doc explicitly lists what the DSL *loses* (Python ecosystem, expressiveness, familiar debugging) and argues the loss is the point ("what can't be expressed can't go wrong"). Specs rarely enumerate their own costs.

## Part II — Language Foundations (§4–§6)
Sol is an envelope `{sol, imprint, body}` where `body` is KV working memory and every value has a *kind* (`data|var|fn|flow|sol|list`). **Imprints have two tiers** (`declared id@v` / `structural ~hash`), "missing" is impossible, and declared imprints are mandatory at persistence, both sides of a `Call`, and Model outputs — with a hard rule that **program-bearing bags (any `fn`/`flow`) can never cross a boundary** (§4.1.4). The bag model is **edit-only**: ops replace exactly their static write set, `Const` is the *sole* whole-bag writer, `Call(id,args,into)` gives the callee only `args` (least privilege) and lands namespaced output at `into` (root forbidden), and **all instruction paths are literals** — no runtime-computed paths (a G2/wave prerequisite). §4.3 pins canonical serialization: BLAKE3, sorted keys, **int `2` ≢ float `2.0`**, and **NaN/±∞ forbidden in Sol data**. §6 unifies privilege: `Map`/`Filter` children see only the element + explicit `imports` (never the parent bag), the same shape as Call targets and prompt slots.
**Surprise:** the cast matrix (§5.2) *forbids* `int→bool`, truthiness, and `str→bool` beyond exact `"true"/"false"` — all meaning-bearing mappings are deliberately funneled into `map_enum`/`default`/`const_set` so the promotion gate can scrutinize them. Casting is representation-only by law.

## Part III — Kernel (§7–§12)
Five op classes (Control, Compute, I/O, Model, Tool); a decision procedure keeps the kernel closed — anything domain-specific is a *registered Call target*, never a new op (`NormalizePhone` is forever a validator). §8 locks **all 17 Control ops** with per-op semantics that *are* the conformance vectors: notably `Loop` raises `Budget.Iter` on exhaustion (**never a silent cap**), `Map` is fail-fast + atomic (no partial list ever lands), `Once` is at-most-once with **fail-loud unknown outcome**, and `Park` (not `Sleep`) is the only wait — with a full "Park-inside-X" matrix and a **reserved runtime-owned `sense` subtree** the Planner forbids writing to. §9 is the closed Compute catalog (checked arithmetic — overflow raises `Type`, never wraps). §10 makes **prompts and queries registered artifacts, not strings** (args-only slots = the injection perimeter; a closed query AST with mandatory `limit` = no query text to inject into). §12 is the determinism core: append-only per-instance ledger enumerating every nondeterminism source, replay-as-pure-function with **hard-refuse on divergence**, and universal intent→result accounting for every write/external Call.
**Surprise:** the **termination theorem** is a real proof obligation, not a slogan — acyclic call graph (recursion *forbidden* in v0; "continue later" is `Park`) + capped loops/lists + deadlined externals + bounded queries ⇒ every program terminates (G1). Boundedness is enforced at plan time, including the DAG check.

## Part IV — Conversion Subsystem (§13–§17)
Conversions are **planner-inserted edges** (never user-authored) that adapt one node's output shape to the next node's expected input. Edge identity is `(tenant, flow_id, producer_nid, consumer_nid)` — **nid-based and version-free** (Amendment #1), so edges survive flow edits; any edit demotes all of a flow's edges to shadow with fast-track re-promotion. The rule set (§14) is a **closed, non-computational** 11-op set (`rename, drop, keep, default, cast, wrap, unwrap, map_enum, path_copy, const_set, trim`) — no rule's output can feed rule *selection* (proven by construction + property test), which is what makes the cold-path **containment theorem** hold: a malicious payload's worst outcome is a wrong *mapping*, structurally downgraded into the class the gate defends hardest. §16 is the safety core: **Structural → Shadow (validate-without-consume) → Canary (bounded consumption + attribution) → Promotion**, all thresholds over **distinct input hashes** (evidence can't be inflated by repetition), with **reach-based tiers** (auto / reviewed-if-reaches-a-write-or-external / locked-for-secret).
**Surprise:** **shadow = validate-without-consume** elegantly solves the bootstrap problem (you don't need an old path to compare against — the consumer's input digest *is* the oracle). And fabricating rules (`default`/`const_set`) escalate to reviewed tier *regardless of reach*, because minting unobserved data is inherently semantic.

## Part V — Learning Subsystem (§18–§21)
Pathway selection is treated as a **classifier with hygiene**: a pick needs top-1 ≥ τ AND margin ≥ δ AND entropy below a ceiling, else it routes to a **mandatory declared fallback** (every decision point must declare one or be plan-time rejected), and **fallback rate is the de-facto drift detector**. Embedding models are **pinned per tenant** — a model upgrade re-embeds all prototypes and drops affected pathways to canary (scores aren't comparable across embedding spaces). **Procedure learning = registration**: a promoted procedure is just a registered Call target inheriting every §10 invariant, mined from ≥5 isomorphic successful subsequences in 30 days. §20 attribution is **deliberately dumb/honest/conservative** — flow-outcome boolean spread over all artifacts used; its documented biases produce false *demotions* (cheap) never false *promotions* (expensive). §21 pre-registers **kill criteria** (converters <60% warm-hit@90d falsifies the core bet; procedures <10% turns@6mo demotes them from headline to experimental).
**Surprise:** the spec **pre-registers falsification bars before the data exists** and puts them in the README — a scientific-integrity move (and the same generic §16 gate serves converters, pathways, procedures, and imprints; only the *agreement predicate* varies).

## Part VI — Runtime & Persistence (§22–§28)
The turn loop is `message → hydrate → Sense freeze → flow gate → program → persist`, with a **normative hydration order** (§22.3) that designs out the "everything is hot" staleness bug (compute recency *from loaded timestamps* before freezing `sense`, and only then touch `last_seen`). v0 has **one active flow + read-only detours** (no flow stack); a flow-requiring intent mid-flow gets an Express-and-defer recorded as an open loop. Park/resume routes user wakes via the flow gate and external wakes via an **event key minted at Park time** (token possession = authorization). §24 maps to Sunjet with a **unified `artifacts` table** (the generic gate's data-model dividend) + CAS version columns. §25 is the 5-point migration doctrine (**refuse unknown versions**; kernel bump ⇒ canary-all). §26 ships real tooling (trace viewer, replay CLI, edge inspector, pathway explainer) that all just read the ledger.
**Surprise:** abandoned parks still get a **termination turn** — a final ledgered turn that runs the enclosing `finally` chain even when the user ghosts, otherwise `finally` would be a lie for any parking flow. Cleanup is guaranteed by the runtime, not hoped for.

## Part VII — Implementation (§29–§30)
The interpreter is a strict **two-phase machine**: a **Planner** that runs *every* static check the spec mandates (schema closure, literal paths + R/W-set derivation, boundedness incl. the DAG acyclicity check, policy-tag presence, Park-position legality, Tee dataflow isolation, query-AST limits, hydration-need derivation) so "a plan that passes is executable by construction", and an **Executor** doing a sequential depth-first walk with ledger appends — replay is the *same executor* fed by the ledger. Crates form a strictly-downward dependency chain rooted at `aelio-sol` (zero internal deps). Build order is P0 (sol + hashing + Planner + Executor + ledger + replay CLI + Control/Compute + Once/CAS + Park/resume + **login golden flow**), then P1 (conversion + generic gate + mutation harness + pathways + prompt/query registries + isolation + tooling), then P2 (procedure mining + metrics + sugar + wave scheduling).
**Surprise:** waves are **spec-ready but not spec-active** — R/W sets are recorded from day one and the wave-legality rule is normative *now*, so parallelism later becomes an executor change, never a spec change. Forethought baked into the data model.

## Part VIII — Server / SDK Topology (§31–§35)
The server **never holds customer tool credentials**: it emits tool-call requests over a persistent reverse channel to the deployer's SDK, which executes with the deployer's creds and returns the result — and this reuses existing locks verbatim (a reverse call is `Park(until:event)`-shaped with a §23 correlation token, deadline as a wire field, §12.4 intent→result ledgering transport-agnostic). Control plane (HTTP, deployer keys) does **versioned artifact pushes** (a push is a new version; pins + migration doctrine apply free, and **push-time Planner validation rejects broken flows at deploy, not runtime**); data plane is one persistent stream carrying turns, wakes, and the reverse tool channel, itself **version-negotiated** (refuse unknown majors). Model calls run server-side with **BYO-key** per tenant; channel adapters (WhatsApp/voice/web) are server-side ingresses producing ordinary turns; v0 is non-streaming and single-node with tenant-shard scale-out later.
**Surprise:** the "no customer keys on the server" B2B2C pitch is framed as a **structural property, not a feature** — it falls out of the reverse-channel-as-Park reuse, and the double-effect hole (deadline-expiry on a *dispatched* write returning retryable `Tool.Transient`) was caught and closed in the App H elaboration (must be `Internal` unknown-outcome).
